## AI 聊天会话管理（1.36.0+114）
- 需求：经期问答新增 清空消息 / 新建聊天 / 历史聊天记录 三项功能，数据互相隔离。
- 实现：聊天存储由扁平 `ai_chat_json`（全局 50 条）改为会话化 `ai_chat_sessions_json`（`ChatSession` 列表，上限 20 个会话 × 每会话 50 条消息）；旧扁平数据在 `ensureLoaded` 时自动迁移为单个会话并清空旧 key。
- Provider 新 API（AiAssistantProvider）：`sessions`/`activeSession`/`chatMessages`/`hasActiveSession`、`startNewChat()`（旧会话保留、回空状态）、`clearActiveSession()`（先清 messages 再移除，流式迟到内容由 isEmpty/越界守卫丢弃）、`openSession(id)`（回看，可续聊）、`appendMessage(msg)`（无会话自动创建，标题取首条用户消息截 20 字）、`updateMessage(session, index, msg)`（流式 flush 用，越界静默忽略、不 touch updatedAt）。
- 隔离机制：流式输出绑定发起时的 `ChatSession` 对象引用 + `_streamingSessionId`；中途新建/切换会话不串写。
- 排序确定性：`_sortSessions` 按 updatedAt 降序、createdAt 兜底；`appendMessage` 用 `msg.timestamp` 而非 `DateTime.now()` 写 updatedAt（否则测试快速连发时间戳相同 → 排序不确定，曾致 2 个测试失败）。
- 会话 ID：`chat_<micros>_<seq>` 自增序号防同微秒重复。
- UI（ai_assistant_screen）：AppBar 问答 Tab 下 消费者包一层 Consumer 显隐"清空"；新建/历史常显；历史为底部弹层（标题/时间/条数/当前标记，点击 openSession 回看）；body 由 Consumer2 → Consumer3 监听 AiAssistantProvider。
- 验证：analyze 0 issue；test 153/153（新增 10 条会话测试）；debug APK 构建成功。
- 旧 `clearChatHistory`/`chatHistory` getter 已随会话化重构移除（无其他引用）。

## UI 设计评审（仅评审，未改码，1.37.0+116 基线）
- 产物：`UI设计评审与优化方案-2026-09-09.md`（项目根目录）。范围：token 体系 + 5 主屏 + 4 图表 + 双主题 + 可访问性。
- **方法**：源码静态审查 + WCAG 2.1 对比度脚本实测（sRGB 相对亮度公式，半透明白按 alpha 合成后计算），非目测估算。综合评分 2.9/5（色彩 3.5 / 排版 3.0 / 组件 2.5 / 无障碍 2.0 / 空间 3.5）。
- **核心结论（对比度）**：实测 13 组关键组合仅 2 组达 AA 4.5:1（15%）。渐变由「中→浅」是根因：brandPrimary #B4564F 白字 4.79 ✓，但末端 brandLight #C97B6F 只有 3.21，叠加白 70/75/90% 后跌到 2.34/2.48/2.91；AI 卡末端 #8B7AB8 白字 3.77、副标题 3.01；警告 SnackBar 白字/黄底 2.25；onSurfaceTertiary #A39A90 白卡 2.77（却用于计数/时间/说明）；硬编码 inkSecondary/深色卡 2.80；error #B4463F/深色卡 2.92。
- **关键可复用铁律**：陶土红 #B4564F 底上只有 100% 白能达 4.5（4.79），95% 恰 4.50，92%/90% 均不足 → 渐变卡层级必须用字号/字重/分隔线，禁用白色透明度。已验算的建议值：hero 改深→中 #8E3F3A→#B4564F（7.19/4.79）；AI 卡 #5B4C82→#6B5B95（7.50/5.91）；浅色 tertiary #7A7269（白卡 4.73，但 tile 底 4.05 不达标 → tertiary 仅限 placeholder/disabled）；深色 tertiary #948B82（4.71）；深色 destructive #E8908C（6.61）；警告 SnackBar 改近黑字 #2A2622（6.67）。
- **工程一致性**：业务代码 65 处硬编码 fontSize（15 文件，10 种字号，10/11/13 三个 token 里没有）；4 套卡片实现；SectionCard/EmptyState/LegendItem 三公共组件**零使用**（stats/home/ai 各写等价空状态）、AppBreakpoints 零使用；navigationBarTheme（height 62）是自绘 _GlassNavBar（64）之外的死代码；动效 6 种时长无 token；日历「今天/选中」外 radiusLg16 + 内 radiusMd8 + 间隙 2 → 圆角不同心（应 外=内+间隙≈10~12）。
- **其他**：日历固定 6 行浪费 47~94px 致小屏日历被挤到折叠线下；格子 42.3（360dp）/47（393dp）与经量快选 33 低于 44 触摸目标；5 种日类型仅靠颜色编码（安全期 #E2DDD2 白卡 1.35 等于不可见）；hero 折叠/长按详情属隐藏交互无提示；设置页分区标题 18px 品牌色 > 卡片标题 16px 中灰（层级倒置）；按钮高度 52/48/默认三套；无骨架态。
- **方案**：P0 7 项（对比度+深色，纯色值替换，预期达标率 15%→85%）/ P1 7 项（组件归一+token 补齐，硬编码 65→0）/ P2 6 项（动态行高、多通道状态编码、可发现性、按钮三档、骨架态）。附三条 grep 门禁脚本与新增 token 清单。
- 待拍板：①渐变保「深→中」还是改实底+装饰圆（我倾向前者）；②安全期是否取消填充（建议留白即安全）。
